Student Roster
Form Automation

From a Zoom Participants screenshot to a reviewed roster
and a separate Google Form for each student.

Michael Kowata

Proposal stage: scope and project foundation established.
Application implementation and OCR evaluation are next.

01 / Problem

One roster, many repeated steps

Instructor workflow

  • Transcribe student names.
  • Copy a form for each student.
  • Match each form link to its student.

Project objective

  • Automate repeated copying and linking.
  • Keep human review for names.
  • Produce a traceable roster.

Expected benefit: less repetitive work. Time savings still need measurement.

02 / Proposed workflow

Upload, review, then generate

1. UploadSelect a local PNG/JPEG in the Sheets sidebar.
2. ExtractOCR reads visible Participants panel names.
3. ReviewCorrect names and remove non-students in a staging tab.
4. ApproveConfirm the roster before generating outputs.
5. CopyCreate one template-based form per approved entry.
6. DeliverWrite matching responder links to a new roster spreadsheet.

The control spreadsheet runs the workflow. The output roster is a separate deliverable.

04 / Scope

A complete path for one supported input

Included

  • One Participants panel screenshot.
  • One operator, account, and template.
  • Sidebar upload and name correction.
  • Separate forms and matched links.
  • Recovery without extra copies.

Deferred

  • Gallery tiles and hidden participants.
  • Scrolling and multiple screenshots.
  • Email delivery and grading.
  • Response aggregation and dashboards.
  • Automatic identity verification.

05 / Technical approach

Google Apps Script and JavaScript

Planned components

  • Code.gs: server workflow.
  • Sidebar.html: file selection and upload.
  • Sheets: review and final roster.
  • Drive and Forms: copies and links.

M2 experiments

  • OCR on fictional-name screenshots.
  • Permissions and execution limits.
  • Upload validation and failures.
  • Persistent state and cleanup.

No manual Drive upload. OCR may require temporary Drive resources.

06 / Evaluation

Define success before building

QuestionPlanned evidence
Are names accurate?Expected roster vs. raw OCR; correction count.
Does each student get the right form?Distinct forms and correct links for all approved entries.
Are questions and responses correct?Template comparison and isolated test submissions.
Can a failed run recover?Interrupt and resume with zero extra copies.

Use synthetic names, including duplicates. Record runtime and limitations. No results claimed yet.
